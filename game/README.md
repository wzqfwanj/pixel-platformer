# 横板像素闯关 demo —— 战士

纯前端、零依赖。渲染全是手写的软件光栅化（一块 Uint32 颜色缓冲 + 一块叠加光照缓冲），
美术全部由代码画出，没有任何图片资源。特效来自 `../pixelfx`（同一工作区里的 pixelfx 库）。

## 跑起来

```
python game/server.py
# 然后打开 http://127.0.0.1:8123/game/index.html
```

必须用 http 打开（ES module 不能走 file://）。服务器根目录是工作区根，所以
`game/` 能直接 import `../pixelfx/src/...`。

## 技能清单

**攻击方式只有一个**：K 键蓄力爆炸。

| 技能 | 操作 | 说明 |
| --- | --- | --- |
| 蓄力爆炸 | 按住 K | 蓄力 0.55 秒，松手或蓄满自动在脚下炸开。伤害 12→30，半径 26→52px，圆形范围 |
| 跳跃 | 空格 | 按住跳更高，带土狼时间和输入缓冲 |
| 冲刺 | Shift / L | 短距离，带无敌帧 |

J 键不再攻击（输入映射里已移除）。

设计上的取舍：

- **只有一个攻击，所以它必须是万能的**。蓄力斩同时承担了远距离、范围、高伤害三种需求：
  蓄满能打到 52px 外、能一次穿透多个敌人、伤害翻倍。
- **蓄满自动出刀**。按住 K 不放，蓄满就自动放，不用记着松手；
  想快点出刀就提前松手（伤害和距离都按当前蓄力量算）。
- **蓄力时保留 70% 移速**。唯一攻击手段需要蓄力，如果蓄力时几乎不能动，
  就变成站桩挨打。现在可以边后撤边蓄力。
- **受击只衰减一半蓄力**，不清零。满蓄被一下打断太挫败。
- **被打断后按住 K 会自动重蓄**。之前只认"按下"这个边沿事件，
  蓄力被打断后玩家还按着键却什么也不发生。

## 两种模式## 两种模式

**启动时先选模式**：进入游戏是一屏选择界面，A/D 或 ←/→ 选，空格/回车确认，
也可以直接按 1 / 2。游戏中按 **M** 随时回到菜单。

- 关卡模式（默认）：`/game/index.html`
- 无尽模式：`/game/index.html?mode=endless`

### 无尽模式

怪从玩家左右两侧刷出来，一波比一波多、比一波硬。没有终点，活多久算多久。

| 时间 | 波次 | 刷怪间隔 | 会出现 |
| --- | --- | --- | --- |
| 0s | 第一波 | 2.6s | 史莱姆 |
| 25s | 第二波 | 2.1s | + 蝙蝠 |
| 55s | 第三波 | 1.7s | + 骷髅 |
| 90s | 第四波 | 1.35s | + 石像鬼 |
| 130s | 第五波 | 1.1s | 全部混合 |
| 180s+ | 无尽 | 0.9s | 全部，血量 2.3× |

三种新敌人：

- **蝙蝠**：会飞，不受重力，走正弦轨迹上下飘，会绕着你盘旋。
- **骷髅**：地面单位，朝你走，间隔起跳越过障碍。
- **石像鬼**：慢、血厚，蓄力后猛冲（速度 4 倍），冲击力大。

几个设计上的取舍：

- 同屏存活上限 18 只。超过就暂停刷怪，等你清理。不加这个上限的话，
  躲角落不推进时敌人会堆积到几百只，直接卡死。
- 怪全部刷在视野外，不会凭空出现在屏幕里。
- 死了就是结束，不自动复活（关卡模式仍会自动回到安全点）。
- 敌人离玩家超过两屏宽会被回收，避免远处堆积。

## 战士这个职业做了什么

- 移动：加速度 + 摩擦，空中控制力比地面弱；可变跳跃高度；0.09 秒土狼时间；0.12 秒跳跃输入缓冲。
- 三段连招：`CFG.combo` 里三段的 前摇/判定/后摇/伤害/攻击范围/特效/震屏 都是数据，
  加职业时照抄这段改数就行。每段在 active 阶段才判定，命中后立刻进 `hitLag`（0.045 秒定格），
  这是打击感的主要来源。
- 蓄力重砸：按住 K 出 `lightning/charge-up` 特效并蓄力，松手在地面砸出
  `impacts/ground-slam` + `explosions/dirt-explosion`，按 42 像素半径结算范围伤害；
  空中按 K 会变成下坠砸地。
- 受伤：0.85 秒无敌、击退、闪白、震屏；血空后倒地 1.1 秒再回到最近的安全点。
- 掉坑：扣 15 血并回到最后站稳的位置（安全点每 0.25 秒记录一次）。

T  火把       C  金币         D  木桩靶
E  史莱姆     S  出生点       X  出口

## 特效怎么接进来的

`fx/fxlayer.js` 是唯一和 pixelfx 打交道的文件：

- 显式列了一张 `LOADERS` 表（`"melee/sword-slash": () => import(...)`），
  只加载用到的 21 个特效，不是整个库。
- 每个特效有自己的 frame（尺寸取特效的 `meta.size`，原点取 `meta.origin`），
  画完把颜色按 alpha 混进场景、把 light 累加进光照缓冲，所以火把、刀光会真的照亮周围。
- 屏幕外的特效不更新（`fx.update` 里做了视野剔除），常驻特效（火把）离开视野时保持不动。
- 战士用一套自定义暖橙调色板 `WARRIOR_PALETTE`，默认刀光是冷蓝的，换成橙金配红战袍。

## 角色素材（黑衣人）

角色改用 **Ninja Adventure Asset Pack**（CC0 1.0，Pixel-Boy & AAA）里的忍者，
并把蓝色衣服重映射成深灰黑，做成"黑衣人"。

- 素材：`game/ref/ninja-blue.png`（原图 64x112，未修改）
- 转换：`tools/build-ninja-frames.mjs` → `entities/ninjaFrames.js`
- 绘制：`entities/warriorNinjaArt.js`（1 倍，16x16 = 一个图块高 + 亮色轮廓光）
- 授权说明：`ASSETS.md`

精灵表布局（由素材自带的 Godot 脚本确认）：

| 维度 | 含义 |
| --- | --- |
| 4 列 | 朝向：下 / 上 / 左 / 右 |
| 行 0-3 | 行走循环（横版只用左/右列的这 4 帧）|
| 行 4 | 攻击 |
| 行 5 | 跳跃 |
| 行 6 | 死亡 |

和之前那 4 张静态图相比，这次拿到了**真正的行走循环**：跑动时腿会摆，
而且素材原画里第 0 帧等于第 2 帧（A-B-A-C 四拍，每只脚各一步），
所以是 3 个不同姿势撑起 4 拍节奏。

攻击仍然只有 1 帧，所以挥砍的视觉重量主要交给 pixelfx 的刀光特效、
命中定格和身体倾斜/拉伸。

关键取舍：

- **1 倍绘制（16x16）**。素材正好一个图块高，和关卡比例一致。
  试过 2 倍（32px = 两格高），比碰撞盒大太多，站在地上像悬空，比例失调。
- **碰撞盒 8x15**。照素材里人物的实际占地调，不是照图片尺寸。
  之前是 10x22 配 32px 绘制，视觉比碰撞大一圈。
- **攻击距离同比缩小**（reach 21~26，原来 27~33），否则小角色的攻击范围会显得离谱。
- **亮色描边**。黑衣人在暗背景上会糊成一团，所以描边用亮灰（#6f7488）
  做轮廓光，而不是常规的深色描边。白色面罩提供第二重对比。

## 相机与抖动

移动时的"抖"有两层原因，都修了：

1. 相机用 `lerp(cam, target, dt*7)` 再 `Math.round`。lerp 每帧推进的比例是小数，
   取整后相机每帧走 0/1/2/3 像素不等，匀速跑动时整个场景的滚动节奏就不匀。
   现在（`world/camera.js`）相机以角色的**整数**位置为准，带 22 像素水平死区，
   死区内完全不动、出死区后 1:1 跟上，相机坐标始终是整数。
2. 角色绘制和相机各自 `Math.round`，两者的舍入相位不同，就会出现相对 ±1 的来回。
   现在角色和相机用的是同一个 `Math.round(cx)`，所以角色在屏幕上（死区内）纹丝不动，
   滚动全部交给相机。

验证方法不是眼看，是逐帧量：

```
node game/tools/jitterpix.mjs    # 像素级：把角色画出来找包围盒，检查每帧位移
node game/tools/test.mjs         # 第 10 项固化了同样的检查，防回归
```

跑动 169 帧的结果：精灵包围盒上沿恒为 14、高度恒为 28、水平位置反向 0 次。

## 蓄力爆炸（K 键，唯一的攻击）

按住 K 蓄力，松手（或蓄满自动）在**脚下**炸开一圈范围伤害。0.55 秒充满。

| 属性 | 轻蓄 | 蓄满 |
| --- | --- | --- |
| 伤害 | 12 | 30 |
| 爆炸半径 | 26px | 52px |
| 地形变化 | 无（只有土爆）| 地面变红闪裂 + 石头飞溅 |
| 其他 | — | 敌人被掀飞、更长的顿帧、更大范围的震屏、追加冲击波特效 |

关键设计：

- **圆形范围，不是单向**。以角色脚下为圆心，前后左右的敌人都吃伤害（实测正前方和身后的
  各 26 伤害）。这是它和普通攻击最大的区别 —— 被围住时也能清场。
- **越近伤害越高**。边缘 70%、圆心 100%。实测近处(5px) 30 伤害、远处(45px) 23 伤害。
- **只有蓄满才让地形变红并溅石头**。这是满蓄的专属表现，也是最直观的"该松手了"信号。
- **爆炸有反作用力**。自己会被震起一点（-60~-100 的垂直速度），落地才继续操作。

### 地形变红与石头飞溅

**蓄满才放**，用的是 pixelfx 的 `impacts/ground-slam`：

> Something lands hard: the floor flashes and cracks, two crescent shock waves race out
> along it, a dust wave and a tall dust cloud rise, rocks erupt, bounce and settle.

也就是：地面闪一下并裂开（默认调色板是红橙色 `#2a1712 → #e8893a`，所以地形看起来变红）、
两道冲击波沿地面推开、尘土扬起、石头喷出来弹跳再落定。

实测起手 0.05 秒时，特效自身的像素里有 20% 是红色 —— 这就是"地形变红"的来源。

**踩过一个大坑：它看起来"只在墙角触发"。**

ground-slam 的尘土和碎石颜色全部由 `stone` 参数派生：

```
light = stone × 1.35 混白    body = stone    shade = stone × 0.64    dust = stone × 1.2 混灰
```

而它的默认 `stone` 是 `#4a3f69`（深紫蓝），本作的地面图块是 `#414c6b`（蓝灰）——
几乎同一个颜色。实测对比度只有 **16**（地面亮度 66，特效亮度 50），尘土和碎石完全
融进地面。只有靠墙时，尘土升到亮砖或天空前面才有轮廓，所以看起来"只有在墙角才触发"。

修法：把 `stone` 换成暖金 `#d8a868`，对比度从 16 提到 35（石头自身的亮度差从 5 提到 110）。
实测蓄满爆炸后，地面区域平均亮度从 54 提到 97（+43），整片地面被染成暖色，效果肉眼可见。

轻蓄和半蓄只放 `explosions/dirt-explosion`（范围小的土爆，不改变地形），
到 85% 以上才追加 ground-slam。这样"满蓄"在视觉上有明确的分界。

早先我自己写过一套碎石物理（`fx/debris.js`，带重力、碰撞反弹），
后来发现 ground-slam 本身就包含石头喷出弹跳落定，两套并存反而重复且混乱，已经删掉。

### 为什么加了"烧痕"层

ground-slam 自身的热度曲线是 `heat(t) = pow(clamp(1 - t/0.8), 1.4)` ——
**0.8 秒后热度归零**，裂缝和火山口的红光全灭，只剩暗色石头。
实测地面提亮超过阈值的时间只有 1.35 秒，主观感受就是"放一下就没了"。

修法是在游戏层加 `fx/scorch.js`（不改上游库）：

- 爆炸时在地上留一块烧痕（颜色层用抖动淡化的暗红 `#3a1a18`）
- 余温光铺到烧痕半径的 1.6 倍，强度随时间用 `pow(t, 0.35)` 衰减
- 生命 4~6 秒，前 2 秒基本不掉亮度，之后慢慢冷掉

实测可见时间从 **1.35 秒提升到 3.30 秒**，峰值提亮 +42，2 秒时仍有 +9。

写这个层时踩了个自己的 bug：亮度系数写成
`min(1, (1-t)/0.1) * pow(t, 0.45)`，而 `t` 是 `life/maxLife`（1 = 刚生成）。
刚生成时 `(1-t)/0.1 = 0`，所以系数恒为 0 —— 一个像素都画不出来，
而且随着 t 变小反而变亮，整个逻辑是反的。改成 `pow(t, 0.35)` 才对。

### 蓄力条

条画在**角色头顶**而不是 HUD 角落：蓄力时玩家视线在角色身上，
抬眼去看左上角会分神。

三段配色，不用读数字就知道攒到哪了：

| 进度 | 颜色 | 含义 |
| --- | --- | --- |
| 0-40% | 冷白 | 刚开始 |
| 40-85% | 橙金 | 有威力了 |
| 85-100% | 亮红 + 闪烁 | 满了，松手就炸 |

条上还有 25% / 50% / 75% 三个刻度。蓄满时角色光晕会加强、条上方加一道亮线。

可见性上踩过一个坑：一开始底板和边框用同一个深色，在暗背景上整条糊成
一根黑带，等于没有。现在外框在暗色主题下用亮灰、亮色主题下用深色。

## 小地图

右上角常驻一块小地图，两种模式都有：

- **剖面线**：每列找地面高度画成一条线，坑就是断口，台阶就是高度变化，浮台单独用暗色标出。
- **玩家标记**：三点小箭头，中间挖空，压在剖面线上也看得清。
- **视野框**：四个角标出当前屏幕范围，知道自己在这关的哪个位置。
- **屏幕外的敌人**：只用亮色点标在屏幕外的那些（视野内的不重复标）。
- **出口**：关卡模式下闪烁提示。

设计上的几个决定：

- 只画线不填色。88x14 像素里填充会占掉 40% 面积却只表示"这里是土"，
  反而把重点（坑在哪）盖住。
- 纵向自适应裁剪。关卡 208x22，但地形只在底部几行变化（上面全是天空），
  先扫出地面的最高/最低点再把这段铺满小地图高度，否则坑和台阶会被压成一条线。
- 边框用亮色。暗色主题下 ink 是纯黑，和背景糊在一起，小地图会"消失"。

## 已知的简化

- 敌人只有木桩靶（不动，练连招）和史莱姆（会走过来咬）两种，都没有攻击前摇。
- 没有音频。
- 只有一关，通关后按 R 重开；没有存档、没有商店、没有技能树。
- 角色是代码画的简笔像素画（26x26），不像手工绘制的精灵那样精致；
  要换真图的话，`warriorArt.js` 那个 `drawWarrior(s, x, y, facing, pose)` 换成贴图就行。
